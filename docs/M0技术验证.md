# M0 技术验证

> 本文记录历史验证范围；当前接口和语法见 [编译与执行 API](编译与执行API.md) 与 [CRules Syntax 1.0](CRules-Syntax-1.0.md)。历史 NativeAOT 标量发布记录不代表本轮新增功能已完成 NativeAOT 发布验收。

后续升级补充：现已提供 `DataObject` 有类型读取和对象初始化支持，详见 [当前接入说明](动态数据与对象初始化.md)。下文的 M0 表格保留初始验证范围；当前已新增 ExpandoObject 动态参数路径；本表为历史证据。宿主可改为 DataObject，不再必须为每个动态键定义 DTO。

2026 年 11 月 9 日在 .NET 10 上完成公开 API 封装路线的技术验证，并建立可运行项目骨架及语句编译原型。DynamicExpresso.Core 固定 2.19.6，源码未 fork；Jint 对比固定为 4.17.0。

## 技术闸门

| 项目 | 证据 | 结论 |
| --- | --- | --- |
| 获取表达式树 | Parse 返回 Lambda.Expression，ParseAsExpression 可用 | 通过 |
| 外部局部变量绑定 | Parameter(ParameterExpression) 保留节点身份 | 通过 |
| 类型推断和转换 | Expression.Type、预期返回类型 Parse | 通过 |
| 多语句统一编译 | Block/Assign/IfThenElse/Return/Label 组合 | 通过 |
| LINQ 捕获语义 | 变量重新赋值、嵌套 Lambda 捕获、参数名称冲突拒绝 | 实验选项通过；严格默认拒绝 |
| LINQ 热路径完全无反射 | 标准 Compile 内部使用 MethodInfo.CreateDelegate | 尚未满足，需要树适配；不应伪报通过 |
| 大变量数 | 100 个局部变量，片段不构造 Func | 通过 |
| 数据隔离 | 同一委托一万次并发输入，编译器并发编译 | 通过 |
| 精度及失败 | decimal 舍入、float 拒绝、整数截断拒绝、除零和溢出不回零 | 通过 |
| 编译不执行业务 | 抛异常的 getter 在编译时不执行 | 通过 |
| 热路径分配 | 预热后标量一万次执行，分配为零 | 通过，范围仅该标量用例 |
| 差分 | 固定种子 50 份规则及 5000 组输入对比原生实现 | 通过 |
| 边界模糊语料 | 固定种子 500 份非法源码，诊断跨度始终合法 | 通过，非完整模糊测试活动 |

主路径只使用公开 API，未使用反射读取上游私有字段、未逐片段 Compile，也未通过 Eval/Invoke/DynamicInvoke 调度执行。当前编译期可使用反射元数据进行成员审计。

## 里程碑状态

M0 的公开 API、强类型绑定和单委托组合路线已验证，项目骨架已建立。M0 同时识别到嵌套 Lambda 的运行时绑定限制：严格默认拒绝并返回 CRL4003，只有实验选项允许运行。完整 LINQ 无反射热路径的技术闸门仍未关闭；不能把核心接口可行表述为全部性能原则已经满足。额外交付的 M1/M2 有限语句原型仍需可信作者和受审计宿主。

.NET 10 官方实现依据：https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Linq.Expressions/src/System/Linq/Expressions/Compiler/LambdaCompiler.Lambda.cs 。EmitDelegateConstruction 会生成 MethodInfo.CreateDelegate 调用。该证据解释了集合基准的绑定开销；不能把相关开销隐藏在“单个外层委托”表述中。后续方案可研究标准树变换或受控编译后端，但不得重新实现表达式解析，也无需 fork DynamicExpresso。

后续优先事项是：冻结业务 Scale 与舍入政策、元数据 schema 投影契约、完整成员白名单和转换审计、运行时异常语句位置、资源限制与长表达式防护，然后实施有界缓存与原子热更新。生产吞吐与尾延迟 SLO 仍需根据实际服务流量确定。

JIT 验证环境为 Windows x64、.NET SDK 10.0.401、运行时 10.0.12。另已使用 10.0.14 AOT 工具链实际发布并运行 NativeAOT 标量解释 profile，13 项必需检查通过；其限制和发布警告见 `NativeAOT支持与限制.md`。Linux 和任意泛型／LINQ 的 AOT 兼容性未获验证。
