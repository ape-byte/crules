# 原生 C#、Jint、CRules 三方性能报告

本文保留 2026-11-10 的三方实际测量，顺序为**原生 C#（Roslyn 构建）、Jint、CRules**。CRules 测量后版本是 `99dda85`，重构前为 `fda9f49`；后续显式声明、字典和 AOT 桥接改动没有在此数据中重新测量。本文重写了说明和入口，没有重新跑基准。

“原生 Roslyn”在这份原始测试中指 **用 .NET SDK/Roslyn 构建的普通 C# 静态方法，通过 Func 委托调用**，不是运行时 CSharpScript，也没有 Roslyn 脚本编译/执行引擎的测量组。不能把下表改称“CRules 对 Roslyn Script 的性能比较”。

## 1. 三方完整循环结果

单位：**毫秒 / 100,000 次**，越小越好。包含每次新建随机上下文、传入、计算及逐项结果校验，不包含规则准备。原生和 CRules 各取 5 个进程的中位数，Jint 各入口 3 个；本表固定使用 **复用 Engine 的 Jint 函数 + CLR 对象** 入口。

| 场景 | 原生 C#（Roslyn 构建） | Jint 函数 + CLR | CRules 强类型 | Jint / CRules 耗时比 |
| --- | ---: | ---: | ---: | ---: |
| S1 小上下文 / 简单规则 | 25.76 | 378.05 | 24.05 | 15.72× |
| S2 小上下文 / 100 局部变量 | 39.07 | 7,372.23 | 39.72 | 185.61× |
| S3 小上下文 / 100 变量 + 分支 | 37.49 | 8,408.18 | 39.68 | 211.89× |
| S4 大上下文 / 简单规则 | 1,020.87 | 1,447.91 | 961.79 | 1.51× |
| S5 大上下文 / 100 变量 + 分支 | 1,000.84 | 25,798.13 | 988.62 | 26.09× |

三方输出使用相同输入及期望值逐项校验。主测采用安全整数/定点语义，没有向 Jint 额外叠加 decimal helper。大上下文包含数组、明细、标签、字典与每次新建的长 payload，构建成本会掩盖规则自身耗时。原生和 CRules 的小差距不能作为“比原生更快”的证明。

原生 `NativeEquivalent` 将同一规则展开为静态方法、禁止内联并通过委托调用；`NativeReference` 是用于校验期望值的独立参考算法，不作为原生性能上界。Jint 的其他入口、准备口径和数值差异见 [与Jint对比测试](与Jint对比测试.md)。

## 2. 重构前后热执行

正值表示变慢。变化使用**同轮耗时比值的中位数**，不是两列独立中位数相除；因此部分行的百分比不能直接由两列重算。

| 场景 | 前 ms | 后 ms | 配对变化 | 比值 95% 区间 | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| S1 | 24.77 | 24.05 | -2.90% | 0.688–1.550× | 不确定 |
| S2 | 32.97 | 39.72 | +1.33% | 0.380–1.881× | 不确定 |
| S3 | 45.62 | 39.68 | -8.66% | 0.631–1.698× | 不确定 |
| S4 | 1,027.41 | 961.79 | -5.17% | 0.728–1.105× | 不确定 |
| S5 | 1,003.29 | 988.62 | -7.18% | 0.813–1.198× | 不确定 |

95% 区间基于 5 个配对 log 比值的 t 区间（df=4）。本测试只有区间下界超过 1.05 才认定确认回退。五个区间都仍覆盖大于 +5% 的变化：**未确认回退，不等于证明零回退**。

补充的固定输入纯调用中，部分原生对照明显漂移，不能用归一化百分比直接归因到 CRules 重构。原始均值、标准差和分配仍保存在汇总中。

## 3. 固定输入标量微基准

BenchmarkDotNet ShortRun：1 launch、3 warmup、3 measurement。以下是测量后版的 **ns/op**，不是上面完整循环的单位或计时范围。

| decimal 场景 | Mean ns/op | 分配 B/op | 说明 |
| --- | ---: | ---: | --- |
| 原生 C# 直接调用 | 39.077 | 0 | 禁止内联 |
| 原生 C# 委托 | 40.742 | 0 | 原生委托基线 |
| Jint | 1,677.389 | 480 | 十进制字符串 helper，含跨边界成本 |
| CRules 强类型委托 | 42.673 | 0 | 已准备规则 |

CRules decimal 前/后为 37.497 → 42.673 ns（+13.8%），原生委托同期 +4.9%，相对归一化 +8.5%。只有 3 次测量，这是一项待确认信号，不是确定的因果归因。

整数路由的强类型微基准接近测量开销；不使用亚纳秒点值宣传超过原生。实验 Lambda 的集合用例也不等同于默认严格模式，相关时间和分配见原始 BDN 数据。

## 4. 编译准备成本

短规则 BDN 的 CRules 解析/审计/树组合/委托编译从 **0.734 → 1.149 ms（+56.5%）**，分配从约 136166 → 146365 B。不能用执行收益掩盖准备成本增长。

另一组独立编译探针，排除上下文构造和执行，各版本各场景 5 个进程；简单场景每进程 200 次，复杂场景 20 次：

| 场景 | 前 ms/编译 | 后 ms/编译 | 配对变化 |
| --- | ---: | ---: | ---: |
| S1 | 1.502 | 2.472 | +60.31% |
| S2 | 46.463 | 45.191 | -1.55% |
| S3 | 61.314 | 63.666 | +6.68% |
| S4 | 1.766 | 1.893 | +23.52% |
| S5 | 73.231 | 77.629 | +1.05% |

两组源码、测量框架和样本不同，不合并为一个“平均编译耗时”。规则应在加载/变更时准备，并复用 executable。

## 5. 调用入口成本

| CRules 入口 | Mean ns/op | StdDev ns/op | B/op |
| --- | ---: | ---: | ---: |
| 强类型单上下文 | 0.274 | 0.332 | 0 |
| 强类型两个 decimal | 14.548 | 1.213 | 0 |
| 运行时 Type 单上下文 | 22.618 | 1.971 | 56 |
| 运行时 Type 两个 decimal | 55.764 | 3.709 | 136 |

Type 入口包括 params 数组、参数检查、值类型装箱和通用适配；强类型入口直接调用委托。单上下文极小点值仅作为该短基准观测，不用于宣称通用零成本。对象创建、动态输入、异步及 AOT 不继承这些结果。

## 6. 环境和校验

| 项目 | 固定值 |
| --- | --- |
| CPU / OS | Intel Core 5 210H，8 核/12 线程，Windows 10.0.26200 x64 |
| SDK / runtime | .NET SDK 10.0.401 / .NET 10.0.12 |
| 依赖 | DynamicExpresso.Core 2.19.6、Jint 4.17.0、BenchmarkDotNet 0.15.8 |
| 主测/编译探针 | 逻辑核心 2，affinity mask 4，DOTNET_TieredCompilation=0 |
| 预热 | 每执行进程至少 2000 次且至少 750 ms |
| BDN | 同一核心，默认 JIT 策略，自身预热；不与主测混合 |
| 随机种子 | 20261109 |
| 记录 | 141 条完整循环记录，其中 135 条计算，共 13,500,000 次输出校验；另 50 条编译记录 |

前后实际加载核心的 IL/签名指纹与对应版本一致，排除误测同一核心。BDN 构建可能改变 MVID/PDB 路径，二进制哈希和 IL 指纹分开保存。最初不固定调度/分层编译的预检样本整体弃用，没有选择性纳入有利轮次。
