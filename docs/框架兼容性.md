# 目标框架与兼容性

CRules 只发布一个 NuGet 包，内含以下四组目标资产；每组都包含 CRules.dll 和 CRules.Abstractions.dll。输入签名、Syntax 1.0 和使用方式不因目标框架而另设版本。

| 包内目标 | 典型选择 | 验证范围 |
| --- | --- | --- |
| netstandard2.0 | 没有专用现代资产的兼容宿主 | 两个标准程序集在 .NET 8 上运行完整回归；net472 消费项目在本机 .NET Framework 4.x 上运行安装测试 |
| net6.0 | .NET 6、以及可选择此资产的后续兼容版本 | .NET 6.0.36 实际运行完整回归和包安装检查 |
| net8.0 | .NET 8；.NET 9 自动选择此资产 | .NET 8.0.28 完整回归，.NET 8/9 包安装检查 |
| net10.0 | .NET 10 | .NET 10.0.12 完整回归和包安装；NativeAOT 范围单独验证 |

源码构建仍使用根目录 global.json 指定的 .NET 10 SDK，源代码语言版本为 C# 14。**构建 SDK、消费项目目标框架、消费项目 C# 语言版本、规则字符串语法，是四个不同概念。** 用 SDK 10 编译 net6.0/netstandard2.0 库，不要求使用者的运行环境安装 .NET 10。

## 自动选择与依赖

NuGet 按消费项目选择最近的兼容资产；例如 net9.0 项目安装 CRules 时选择 net8.0，不需要单独发布 net9.0 包或手选 DLL。

| 目标组 | 直接包依赖 |
| --- | --- |
| netstandard2.0、net6.0 | DynamicExpresso.Core 2.19.6、System.Text.Json 8.0.6 |
| net8.0、net10.0 | DynamicExpresso.Core 2.19.6，JSON 使用共享框架 |

PolySharp 1.15.0 只用于构建阶段补齐旧目标缺少的语言标记/类型，不是消费者的运行时包依赖。标准资产的 System.Memory、ValueTask 等基础能力通过 JSON 的正常 NuGet 传递依赖还原。不要只复制一个 DLL 而跳过依赖还原。

底层 DynamicExpresso.Core 2.19.6 提供 netstandard2.0 资产，因此 CRules 的下限与它对齐；JSON 和宿主其他依赖仍需共同满足目标平台。netstandard2.0 不是一个可独立启动的运行时，不存在“在 .NET Standard 运行时直接运行”的验收方式。

## 使用范围

- 旧目标使用兼容的空参数检查、类型/动态代码能力检查、字符串/字典辅助、数值解析等实现，公开 API 保持一致。
- 规则语法相同，不代表所有运行时拥有相同 BCL 成员。例如旧 .NET Framework 的 Dictionary 不提供某些现代成员；规则只能调用其宿主实际存在的成员，不会为宿主凭空增加方法。
- CompileOptions 的 required 属性、宿主示例的原始字符串等涉及消费项目的 C# 编译器能力。较旧编译器可优先使用 Func 泛型入口；直接构造带 required 的配置类需要支持该语言特性的编译器。目标 net6.0 不等于所有示例都能由 SDK 6/C# 10 原样构建。
- net472 安装检查使用本机 CLR 4.x（注册版本 4.8.09221），不代表已在原始 .NET Framework 4.7.2 安装环境、全部 Mono/Unity 或所有 netstandard2.0 宿主上验收。
- 本轮没有扩展 NativeAOT 的承诺范围；已验证的 .NET 10 Windows/Linux x64 配置见 [NativeAOT支持](NativeAOT%E6%94%AF%E6%8C%81.md)。普通目标兼容不等于任意旧版本 AOT 通过。

## 可复现回归

主测试项目覆盖 net6.0、net8.0、net10.0，各 923 项，其中包含 694 项 Roslyn 差分检查；每次还检查实际运行时主版本和两个被测程序集的 TargetFrameworkAttribute，避免误用其他目标资产。net6 使用兼容的测试宿主/适配器与 Roslyn 4.8，net8/net10 使用 Roslyn 5.0；参照语言仍固定 C# 9，不改变规则语法契约。

```powershell
dotnet test tests/CRules.Tests -c Release -f net6.0
dotnet test tests/CRules.Tests -c Release -f net8.0
dotnet test tests/CRules.Tests -c Release -f net10.0
```

需要对应运行时。当前机器的 .NET 6 安装在 `.tmp/dotnet6`，没有改系统安装；复现时可以显式传入测试宿主：

```powershell
dotnet test tests/CRules.Tests -c Release -f net6.0 -- "RunConfiguration.DotNetHostPath=C:/Work/Project/ClrRule/.tmp/dotnet6/dotnet.exe"
```

要验证**标准资产本身**，先构建，再让测试项目直接引用该资产，在 .NET 8 上执行同一套测试。标准测试使用独立输出目录和锁文件，不污染正常多目标测试的还原结果：

```powershell
dotnet build src/CRules/CRules.csproj -c Release -f netstandard2.0
dotnet test tests/CRules.Tests -c Release -f net8.0 -p:CRulesTestAssetFramework=netstandard2.0
```

除回归外，独立 PackageReference 项目分别在 net6.0、net8.0、net9.0、net10.0 和 net472 上执行 JIT/解释两模式、字典、Type 入口、空值、对象、JSON 和异步结果共 12 项安装检查，并核对实际选中的包资产。验证数据保存在 [多目标验证记录](data/compatibility/2026-11-10/verification.json)。
