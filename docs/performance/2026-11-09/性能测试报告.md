# CRules 与 Jint 性能测试报告

本文保留早期 BenchmarkDotNet 微基准结果。随机新建 context、十万次计算及 Jint 多种单例入口的综合结论，请先阅读 [性能测试对比：文字版](../../性能测试对比.md) 和 [交互 HTML](../2026-11-10/index.html)。两批测试的输入、生命周期和计时范围不同，数值不可直接混用。

2026 年 11 月 9 日对最终实现运行 23 个 BenchmarkDotNet 场景。核心与兼容测试 109 项通过；另有 13 项实际 Windows x64 NativeAOT 必需检查通过。以下数据均取自随附原始结果，不表示生产流量下的容量承诺。

## 测量环境和方法

Windows 11，Intel Core 5 210H，x64；SDK 10.0.401，JIT 运行时 .NET 10.0.12；DynamicExpresso.Core 2.19.6，Jint 4.17.0，BenchmarkDotNet 0.15.8。Release，无调试器。ShortRun 使用 1 次进程 launch、3 次 warmup、3 次 measurement，MemoryDiagnoser 记录分配和 GC。依赖与源码哈希见 validation 目录。

本轮为可重复的初始基线。只有 3 个测量迭代，误差区间较宽；尤其路由标量仅为纳秒级，不应以其比值宣称优于原生 C#。正式性能门禁需要增加独立 launch、迭代和目标部署环境。全部原始 CSV、JSON、HTML 及统计误差保留在 raw/results。

## 结果应如何使用

RoutingBenchmarks 比较同一整数与布尔决策。Jint 使用已经准备的函数、原生 JS 对象和预分配参数数组，执行中不重复 Parse、不经过 CLR 对象反射包装；CRules 使用已取得的强类型委托。原生直接调用禁用内联，另列原生委托基线。该微小规则的固定输入不能代表整个代理路由系统。

AccountingBenchmarks 在 C# 与 CRules 中使用 decimal。Jint 每步经 decimal 辅助函数，并以字符串往返 JS 边界，确保相同数值和舍入语义。因此 JintDecimalHelpers 包含字符串转换和互操作成本，不能把该数据解释成纯 JavaScript Number 算术的差距。各实现 Setup 先检查结果一致。

CollectionBenchmarks 比较相同阈值过滤和求和，10、100、1000 个元素的总和均在 JS 安全整数范围。原生及 CRules 为 LINQ，Jint 为 filter/reduce。LINQ 迭代器、闭包和标准表达式树内部委托绑定会产生分配；不能把标量零分配承诺扩展到此场景。结果显示与原生 LINQ 的差距也应保留，不能只展示比 Jint 更快的一侧。

CompilationBenchmarks 是稳态重复准备，不是进程冷启动：ClrParseAuditCompile 包含扫描、上游绑定、审计、组合、Compile 和指纹；JintPrepareAst 仅产生 AST；JintPrepareCreateExecute 还创建 Engine 并求值。产物与工作量不同，应分别用于评估发布成本和摊销，不能直接宣称编译器优劣。

HostLifecycleBenchmarks 是代表性 JSON 输入输出场景：CRules 反序列化强类型快照并执行，Jint 每次创建带预算的新 Engine、解析 JSON、冻结本例上下文并输出 JSON。该场景仅测输入转换、规则执行和输出序列化，不包含完整业务服务的调度、数据获取或事务。

## NativeAOT 验证与开销

AOT 编译器及 runtime 固定 10.0.14。实际二进制输出 DynamicCodeSupported=False，13 项必需检查通过；实验 LINQ 在解析阶段失败并单列为不支持。默认 JIT 模式明确返回 CRL4004，支持的动态标量规则须显式选择 Interpreted。

原生验证程序各执行 100000 次，预热 10000 次；以下为单进程 Stopwatch 粗测，不是与上述 BDN 同等统计力度的结果。解释模式的装箱、帧和调用有分配开销，不能沿用 JIT 的零分配目标。

```text
PROFILE Interpreter: ns/op=560.92; B/op=520.000; operations=100000
PROFILE NativeDelegate: ns/op=26.48; B/op=0.000; operations=100000
```

详细的支持边界、元数据保留方式和未屏蔽的上游 AOT/裁剪分析警告见 ../../NativeAOT支持与限制.md。当前不声明动态规则可以在 NativeAOT 中生成本机机器码。

## 复现命令

```powershell
dotnet restore CRules.slnx --locked-mode
dotnet test CRules.slnx -c Release
dotnet run --project benchmarks/CRules.Benchmarks -c Release -- --verify
dotnet run --project benchmarks/CRules.Benchmarks -c Release -- --lifecycle docs/performance/repeat/lifecycle.json
dotnet run --project benchmarks/CRules.Benchmarks -c Release -- --filter '*' --job short --exporters json --artifacts docs/performance/repeat/raw
dotnet publish tests/CRules.AotSmoke -c Release -r win-x64 -o .tmp/aot
./.tmp/aot/CRules.AotSmoke.exe
```

正式复测可增加 --launchCount 3 --iterationCount 10。运行基准时避免同时编译或发布其他项目，且不要在 Engine 使用期间覆盖其程序集。
