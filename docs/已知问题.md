# 已知问题与边界

本文区分已复现缺陷、明确的语法差异和宿主责任。它不把“编译通过”解释成完整 C# 或任意不可信代码可安全运行。完整支持清单见 [语法参考](语法参考.md)，AOT 单独见 [NativeAOT支持](NativeAOT支持.md)。

## 1. 已复现缺陷

### 自定义委托适配

API 泛型约束接受任意 Delegate，但当前通用调用适配器使用推断的表达式树委托类型。自定义委托与推断的 Func 不一致时，编译可能直接抛 `ArgumentException: Argument types do not match`，没有转成 Compilation.Diagnostics。

```csharp
// 当前可能直接抛异常；不要把此例当作支持示例。
public delegate decimal PriceRule(decimal amount, decimal rate);
// compiler.Compile<PriceRule>("return amount * rate;", ["amount", "rate"]);
```

当前使用 `Compile<Func<decimal, decimal, decimal>>` 或 CompileOptions 的 Type 入口。本文只记录缺陷，没有通过文档更新修复该实现。

### 编译诊断不是覆盖所有异常的总包装

常规语法/绑定错误返回结构化诊断；参数配置错误按 API 契约抛异常。除此之外，自定义委托、缺失 AOT 任务元数据等边界仍可能直接抛异常。宿主编译入口应处理诊断和异常两类结果。out 改写中的局部限额错误目前可能为 CRL3001，而普通限额通常是 CRL4001。

### 表达式绑定与完整 C# 有差距

目标类型 new()、数组和初始化器是有限位置的结构适配，不是 Roslyn 全语法解析。逐字字符串、nullable 三元分支推断、复杂泛型/重载或嵌套组合可能被上游拒绝。可改成明确局部类型、显式具体构造、显式 nullable 转换，并将复杂表达式拆成多条已初始化局部。

例如返回 decimal? 时，`return enabled ? null : 2m;` 不应假设能按 C# 目标类型条件表达式完成绑定；写 `return enabled ? (decimal?)null : 2m;`，或使用 if/else 分别返回。

## 2. 明确的语法差异

| 场景 | 当前行为 / 替代写法 |
| --- | --- |
| `const` | 每次执行初始化的只读绑定；只支持 `const name = expr;`，不是原生 typed const |
| 声明 | 必须初始化，每条一个变量；不支持先声明后走确定赋值分析 |
| 变量遮蔽 | 不得遮蔽形参或可见外层局部 |
| nullable 引用 | 接受局部末尾 ? 注解，没有完整流分析或非空警告；引用返回契约都可能返回 null |
| 裸 List | CRules 专有推断语法；空/全 null/不兼容元素需显式 List<T> |
| 裸 Dictionary | 不推断键值类型，写 Dictionary<K,V> |
| out var | 直接调用/if 可用；短路或三元表达式先初始化局部，再 out |
| 方法调用 | 公开方法可独立调用；任意宿主 ref/out、函数声明、递归不支持 |
| 属性与索引赋值 | 仅局部和可写泛型字典索引；普通 DTO 属性、数组/List 索引写入不开放 |
| 对象初始化 | 不承诺 required 成员等全部静态检查；结果完整性由宿主验证 |
| switch | 仅常量标签和最终默认分支的表达式；不支持模式和任意嵌入位置 |
| Lambda/LINQ | 默认严格模式拒绝；实验开关不保证无运行时绑定或 AOT 可用 |
| 字符串 | 普通转义字符串可用；逐字、插值、原始字符串不在当前支持清单 |
| 控制流 | 无循环、foreach、try/catch、throw 语句、using、lock 或规则内部 await |

缺失可达 return 路径会失败，不会把默认值作为结果；完整 if/else 分别 return 合法。

## 3. 动态数据与精度

ExpandoObject 的成员缺失/类型错误主要在执行时发现，自定义 DynamicObject 未完整验收。动态对象、传入字典没有自动复制或冻结。IsMemberAllowed 非空时无法静态审计动态访问，会拒绝该绑定。

DecimalOnly 不把所有数值自动变成 decimal：浮点子树被拒绝，整数算术也可能因结果不是 decimal 被拒绝。decimal 仍有有限范围、有限精度和舍入，不能宣传为“任何精度问题都不存在”。DataObject.GetDecimal 使用 System.Text.Json 的 decimal 读取语义，过多小数位可能按该语义舍入；FromDictionary 先执行序列化，不是任意对象安全快照。

## 4. 执行与隔离

- 编译限额不是执行超时/内存隔离。允许的宿主方法可能阻塞、抛错或修改外部状态，方法内部不会被递归审计。
- IsMemberAllowed 在内置审计上进一步限制成员，不构成完整进程内不可信脚本沙箱。
- ExecuteAsync 不自动切换线程。传给它的取消令牌只在开始前检查，不能强制停止已经执行的规则/方法。
- null Task 和“Task 正常完成返回 null”不同；前者不可等待，后者按原值返回。
- 顶层返回类型白名单不是递归对象图或资源对象校验。object、DTO 或异步泛型结果仍需宿主检查实际内容。
- 局部变量每次独立，但共享输入/宿主服务的线程安全仍由调用方负责。
- 没有内置规则存储、缓存淘汰、版本、原子热更新、执行跟踪或运行异常的准确源码行号。

## 5. NativeAOT 边界

Windows/Linux x64 的指定用例已真实发布并执行通过，但仍有 IL2026、IL3050 等裁剪/AOT 分析警告。必须用 Interpreted；类型自动可见不等于原生代码或元数据自动保留。宿主还需保留 DTO、方法、已知闭合泛型构造。运行时从未出现过的任意值类型泛型实例不能视为可用。

ExpandoObject 只有单字段 decimal 读取转换的实际探测结果，不能扩大为全 DLR 支持；实验 LINQ 在真实 AOT 中仍失败。测试覆盖、构造保留和复现命令统一见 [NativeAOT支持](NativeAOT支持.md)。

## 6. 性能结论的有效期

[性能报告](性能报告.md) 测量的是 `99dda85` 与重构前版本，早于后续显式声明、字典和 AOT 桥接修复。它不是当前工作区每个新功能的复测结果。原生基线是 Roslyn 构建的普通 C# 方法，不是运行时 Roslyn CSharpScript；也没有证明 CRules 比原生 C# 更快。

JIT 强类型标量零分配结果不能套用到 Type 入口、集合/Lambda、对象构造、动态输入或 AOT 解释执行。未确认热执行回退不等于证明零回退，准备阶段成本增长仍需保留。

## 7. 问题复现所需信息

复现应包含规则文本、CompileOptions 或泛型签名、CompilerOptions、最小输入、预期输出和实际诊断/异常；AOT 问题还需 RID、SDK、ILCompiler/runtime 版本、元数据保留配置及真实产物日志。不要仅提供宿主 C# 能编译作为规则语法应当支持的依据。
