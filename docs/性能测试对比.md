# CRules、Jint 与原生 C# 性能复测

测试日期：2026-11-10。实际重跑重构前 `fda9f49` 与当前核心 `99dda85`，使用相同 benchmark 工具、输入和依赖。当前交互入口见 [重新设计的性能报告](performance/2026-11-10/index.html)。旧主交互 HTML 已移除，历史原始 JSON/CSV 保留。

## 本轮结论

本轮五种已有规则未确认超过 5% 的强类型热执行回退，但这不等于证明零回退。 S1, S2, S3, S4, S5 的区间仍覆盖 +5%，测量不确定性需要保留。 补充纯调用中部分原生对照也明显漂移，相关归一化值不能用来断言重构导致回退或提升。

编译准备的配对中位变化为 -1.5%～+60.3%。短规则 BDN 编译微基准为 0.734 → 1.149 ms（+56.5%），存在准备成本增长。这部分属于加载或规则变更成本，不能用热执行优势掩盖；应编译后复用。

回退判断覆盖既有规则的强类型调用路径；新增运行时 Type 入口单独测量。NativeAOT、动态 ExpandoObject、异步等待和所有新语法组合未在本轮建立完整的性能基线。

## CRules / Jint / 原生 C#：完整循环

以下单位为 ms / 100,000 次。全部包含每次构建随机 context、传参、计算、逐项结果校验；不包含规则准备。CRules 与原生同构方法各取 5 个独立进程的中位数，Jint 各入口取 3 个进程的中位数。

| 场景 | CRules 强类型 | Jint 函数 + CLR | Jint SetValue | Jint 函数 + JSON | 原生 C# 同构委托 | Jint CLR / CRules |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| S1 小 context / 简单 | 24.05 | 378.05 | 411.68 | 1,039.37 | 25.76 | 15.72× |
| S2 小 context / 100 变量 | 39.72 | 7,372.23 | 7,626.14 | 4,986.96 | 39.07 | 185.61× |
| S3 小 context / 100 变量 + 分支 | 39.68 | 8,408.18 | 8,359.71 | 5,204.60 | 37.49 | 211.89× |
| S4 大 context / 简单 | 961.79 | 1,447.91 | 1,575.43 | 21,005.90 | 1,020.87 | 1.51× |
| S5 大 context / 100 变量 + 分支 | 988.62 | 25,798.13 | 22,893.74 | 33,485.40 | 1,000.84 | 26.09× |

CRules：准备一次后调用强类型委托。Jint：每个进程仅创建一个 Engine，分别使用 CLR 对象函数调用、SetValue + 已解析 Evaluate、JSON 转换函数调用，入口没有混合。原生 C#：相同规则展开成静态方法，禁止内联，通过 Func 委托调用。独立循环参考算法只用于期望值校验，不能代表原生 C# 性能上界。

主测使用安全整数/定点语义，没有额外给 Jint 叠加 decimal helper 成本；这不表示任意 decimal 算法可直接替换为 JS Number。

## 环境、验证与复现

Intel(R) Core(TM) 5 210H · 8 核 / 12 线程 · Windows 10.0.26200 x64 · SDK 10.0.401 / .NET 10.0.12 · DynamicExpresso.Core 2.19.6 · Jint 4.17.0 · BenchmarkDotNet 0.15.8。

完整循环与编译探针固定逻辑核心 2（affinity mask 4），统一设置 DOTNET_TieredCompilation=0；各执行进程至少预热 2,000 次且不少于 750 ms。BDN 使用相同核心、默认 JIT 策略及自身预热。两类计时不混合。最初默认调度/分层编译的预检样本整体弃用，没有挑选其中更有利的轮次进入正式结果。

固定随机种子 20261109。141 条完整循环记录，其中 135 条计算记录共 13,500,000 次逐项校验，另有 6 条构建基线；50 条编译记录。旧/新实际 BDN 工作进程加载的核心 IL/签名指纹分别与对应版本一致，排除了误测同一份核心。BDN 重建可能改变 MVID/PDB 路径，因此二进制 SHA 也保留，但不要求与直接构建完全相同。
