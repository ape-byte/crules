# 构造与执行

本文说明怎样构造 compiler、输入签名和 executable，以及怎样传值。规则代码本身的声明、分支和集合语法统一见 [语法参考](语法参考.md)。所有公开类型都在 `CRules` 命名空间。

## 1. 两类配置

| 类型 | 生命周期 | 内容 |
| --- | --- | --- |
| `CompilerOptions` | 一个编译器 | 执行后端、数值策略、额外类型、成员策略和编译限额 |
| `CompileOptions` | 一次编译 | 函数体 `Code`、输入 `Parameters`、必需的 `ReturnType`、可选 `Name` |

`RuleCompiler` 构造时复制额外类型列表，编译时复制参数列表。每次编译的类型注册独立，不污染后续编译。

## 2. 三种编译入口

### 单输入泛型入口

```csharp
var compiler = new RuleCompiler();
var executable = compiler.Compile<decimal, decimal>(
    "return amount * 0.9m;", parameterName: "amount", name: "Discount")
    .RequireExecutable();
decimal result = executable.Execute(100m);
```

签名为 `Compile<TInput, TResult>(string code, string parameterName = "ctx", string? name = null)`。上下文只是普通 C# 对象；输入也可以是数值、字典、DataObject 或 ExpandoObject。没有必须实现的上下文接口。

### 多输入/无输入委托入口

```csharp
var multiple = compiler.Compile<Func<decimal, decimal, decimal>>(
    "return amount * rate;", ["amount", "rate"], name: "Multiply")
    .RequireExecutable();
decimal value = multiple.Execute(100m, 0.9m);

var constant = compiler.Compile<Func<decimal>>("return 1m;", [])
    .RequireExecutable();
decimal one = constant.Execute();
```

签名为 `Compile<TDelegate>(string code, string[] parameterNames, string? name = null)`。当前稳定使用 `Func<…>`；自定义委托有已复现的适配缺陷，见 [已知问题](已知问题.md#自定义委托适配)。不支持 `Action`/void 返回签名。

### 运行时 Type 入口

<!-- host:runtime -->
```csharp
using CRules;

var executable = new RuleCompiler().Compile(new CompileOptions {
    Code = "return amount * rate;",
    Name = "Multiply",
    ReturnType = typeof(decimal),
    Parameters = [new("amount", typeof(decimal)), new("rate", typeof(decimal))]
}).RequireExecutable();

object? result = executable.Execute(100m, 0.9m);
Console.WriteLine((decimal)result!); // 90.0
```

`InputParameter` 是 `(string Name, Type Type)`。`Parameters` 默认空列表，表示无参数；`Code` 和 `ReturnType` 必填。返回类型不会从 `return` 语句自动推断。

`Name` 只是可选函数描述，不注册全局函数，不提供递归、同名覆盖、规则 ID 或版本管理。

## 3. 参数名称、类型与传入方式

- 名称区分大小写，必须是合法标识符，不可重复，不占用关键字、可见类型名或 `__crules_` 前缀。
- 名称数量必须与委托形参数量一致。单输入默认 `ctx`，多输入没有隐含的 `ctx`。
- Execute 始终按位置传参，不按名称查字典。参数名称用于代码绑定和诊断。
- 形参绑定只读，不能 `ctx = ...`；引用对象没有被冻结，方法和字典索引写入可能修改对象内容。
- void、ref/out/in 形参、指针、ref struct 和开放泛型签名不在当前支持范围。

运行时 Type 入口额外验证数量、类型与 null。它不把字符串转换成数值，也不自动把传入的装箱 int 当作 decimal。传一个 null 引用参数时，写 `Execute(new object?[] { null })`，避免把 null 解释成整个 params 数组。

## 4. 类型自动可见与额外类型

输入和返回类型及其数组元素、泛型实参自动可见。例如返回 `Dictionary<string, List<Decision>>`，规则可以直接写 Dictionary、List、Decision 类型名。不扫描整个程序集，也不递归注册 DTO 的所有属性类型。

签名以外的类型通过配置补充：

```csharp
var compiler = new RuleCompiler(new CompilerOptions {
    ReferencedTypes = [typeof(StringComparer), typeof(MyFunctions)]
});
```

这个片段假定宿主自己定义 `MyFunctions`。泛型额外类型通常注册定义，例如 `typeof(List<>)`、`typeof(Dictionary<,>)`。基础类型和 Math、MidpointRounding、Enumerable 已内置。不同类型的同名冲突返回 `CRL2002`。

`ReferencedTypes` 解决类型名称解析，不是成员授权清单，也不是 AOT 裁剪保留声明。成员策略是 `IsMemberAllowed`，AOT 要求见独立文档。

## 5. 返回类型与 Execute

| 返回契约 | 当前支持 |
| --- | --- |
| 标量、字符串、DTO、可空值 | 支持；引用类型和 Nullable<T> 可返回 null |
| 数组、List<T> | 支持物化结果 |
| Dictionary<K,V>、IDictionary<K,V>、IReadOnlyDictionary<K,V> | 支持；接口目标需要显式构造具体类型 |
| Task、Task<T>、ValueTask、ValueTask<T> | 支持等待宿主任务 |
| void、Delegate、Expression、任意 IEnumerable/惰性序列 | 顶层返回签名拒绝，不能据此推断完整递归结果类型校验 |

泛型 `Executable<TDelegate>.Execute` 是一个委托属性，直接按签名调用。非泛型 `Executable.Execute(params object?[])` 返回 object；两者都不在执行时使用 DynamicInvoke。运行时入口有数组、装箱、校验和通用适配成本。

Executable 暴露 `Code`、`Name`、`ReturnType`、只读 `Parameters`、`ExecutionMode`。不内置编译缓存；规则加载/变更时编译，宿主保存句柄。并发调用的局部变量独立，共享可变输入与宿主服务仍需宿主协调。

## 6. 异步执行与取消

<!-- host:async -->
```csharp
using CRules;

var executable = new RuleCompiler().Compile<PriceService, Task<decimal?>>(
    "return ctx.CalculateAsync();").RequireExecutable();

// 保留有类型的 Task<decimal?>。
decimal? first = await executable.Execute(new PriceService());
// 通用入口返回 ValueTask<object?>，会等待任务并取出结果。
object? second = await executable.ExecuteAsync(new PriceService());
Console.WriteLine($"{first}; {second}"); // 2; 2

public sealed class PriceService {
    public Task<decimal?> CalculateAsync() => Task.FromResult<decimal?>(2m);
}
```

规则字符串里写 `return ctx.CalculateAsync();`，不写 await。同步返回值也可调用 ExecuteAsync，在当前线程计算后完成，不自动 Task.Run。Task/ValueTask 异常和取消向外传播；非泛型任务完成返回 null。ValueTask 每次执行结果只消费一次，重复调用 ExecuteAsync 会重新执行规则。

`ExecuteAsync(object?[] arguments, CancellationToken cancellationToken)` 只在开始前检查取消，不会强制中断已经开始的规则或 I/O。要取消宿主 I/O，将 CancellationToken 作为普通规则参数传给宿主方法；执行结果仍由该方法处理取消。

## 7. CompilerOptions 完整配置表

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| ExecutionMode | JitCompiled | 编译委托或显式 Interpreted；AOT 必须后者 |
| DecimalOnly | false | 拒绝浮点子树和非 decimal 算术；不重写源码数值类型 |
| AllowRuntimeLambdaBinding | false | 嵌套 Lambda/LINQ 实验开关，非 AOT 兼容承诺 |
| ReferencedTypes | 空 | 签名之外的类型补充 |
| IsMemberAllowed | null | 可选逐成员策略，在内置审计之外进一步检查 |
| MaxSourceLength | 65536 | 整条源码长度 |
| MaxExpressionLength | 16384 | 单个表达式片段长度 |
| MaxStatements | 1000 | 语句与 switch 标签数量限制 |
| MaxDepth | 32 | 代码块、分支、表达式括号与类型嵌套的限制 |
| MaxLocals | 256 | 整条规则的局部声明计数，包括 out 声明/丢弃值 |
| MaxTreeNodes | 50000 | 表达式树审计节点限额 |

各限额必须为正，模式必须为有效枚举值。限额约束编译工作，不是运行超时、内存配额或宿主调用次数上限。

内置审计拒绝反射、文件、网络、线程、诊断命名空间的相关成员及 Type、Environment、Random、DateTime、DateTimeOffset、GetType 等访问；可选策略还检查构造、方法、属性/字段、初始化 setter、集合 Add 和索引器 setter。它不把可信宿主方法变成沙箱，方法内部行为不会被递归审计。

## 8. 诊断与异常

`Compilation.Success` 表示取得 executable 且无诊断；失败查看 `Diagnostics`，或用 `RequireExecutable()` 抛出 InvalidOperationException。`RuleDiagnostic` 包含 Code、Message、UTF-16 `Span`、从 1 开始的 Line/Column，以及 Point/Expression/Statement 精度。嵌套 Lambda、out 或结构改写无法精确定位时降级为片段范围，不承诺运行异常的规则行号。

| 错误码 | 含义 |
| --- | --- |
| CRL1001 / CRL1002 | 边界、分隔符、标识符或空表达式错误 |
| CRL2001 | 不支持的语句或语句形态 |
| CRL2002 | 名称无效/重复/保留、类型名冲突或输入签名错误 |
| CRL2003 / CRL2004 | 类型无法推断、变量/赋值目标无效 / 只读绑定被赋值 |
| CRL2005 / CRL2006 | 缺失 return 路径 / 不可达语句 |
| CRL2007 / CRL2008 | 返回签名不支持 / new() 没有可构造的具体目标 |
| CRL2010 / CRL2011 | switch 结构或标签、选择值错误 |
| CRL3001 | 上游表达式解析、类型或转换错误 |
| CRL4001 | 编译资源限额（部分局部 out 限额目前可能表现为 CRL3001） |
| CRL4002 / CRL4003 | 成员/数值/树审计拒绝 / 严格模式嵌套 Lambda 拒绝 |
| CRL4004 | 无动态代码能力却选择 JitCompiled |

缺少代码/签名等 API 调用错误抛参数异常。执行异常不会转成编译诊断或零值。仍存在少量直接抛出异常的编译边界，见 [已知问题](已知问题.md)。
