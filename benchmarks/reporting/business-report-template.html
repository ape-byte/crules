到底测了什么

相同输入与计算语义

  • 固定种子 20261109，每轮 100,000 个不同的随机 context。各实现重放完全相同的数据。
  • 每次循环创建新的根对象、Request、Pricing、数组；大对象还创建 64 个明细、128 个指标、16 个随机标签、32 个 metadata 字段和 4096 字符 payload。
  • 100 个变量是 v0 到 v99，后一个依赖前一个，最终结果消费 v99；不是 100 个未使用的声明。
  • 复杂分支包含 8 组 if / else if / else 与嵌套 if，共 32 个条件节点。随机 flags 和 Vip 覆盖不同路径。
  • 使用精确安全整数／定点计量，所有输出小于 253。每个结果与独立参考实现逐项比较，避免 decimal 字符串 helper 的额外互操作成本决定结论。

计时和内存边界

  • 规则只准备一次；主计时从随机对象构建开始，到输入转换、计算和逐项校验结束。没有把十万个 context 预先建好。
  • 每个“场景 × 实现 × 轮次”使用独立进程；每种组合 3 轮，原主测试旋转实现顺序。SetValue 单例入口按补充要求另批测量 3 轮，种子、算法和引擎版本不变。每个子进程预热 2000 次，随后强制 GC，再开始计时。
  • BuildOnly 只构建对象，是单独基线。独立 GC 和测量噪声会影响时差，因此不机械相减来声称精确的引擎耗时。
  • 单例 SetValue 模式只创建一个 Engine，预先定义函数和解析 decide(ctx)，每次 SetValue 换成新 CLR context 后 Evaluate。单例函数模式用参数传 context，另有包含序列化与 JSON.parse 的单例 JSON 模式。
  • Jint 隔离入口每次新建 Engine，使用缓存 AST、JSON 与深冻结；有语句、内存、递归预算，生命周期成本与复用入口不同。
  • 所有单例测试均为串行调用，不代表 Jint Engine 可被多线程并发共享。本页测 JIT 模式，不包含 NativeAOT；原生 C# 参考路径使用循环算法，只用于基线和正确性，不代表原生代码性能上界。
